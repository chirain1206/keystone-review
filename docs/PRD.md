# PRD：WoW M+ AI 复盘教练（暂名）

> 阶段 2（产品定义与需求）产出 · 版本 v1.0 · 依据 docs/product-definition.md
> 读者：开发与 QA。每条需求含唯一编号与可检查的验收标准，达到"开发时无需再问需求"的零歧义。

## 背景与目标

魔兽世界大秘境中高端玩家普遍存在"手里有 log、但看不懂、更不知道下一步怎么练"的问题。现有工具（Warcraft Logs / Raider.IO / WoWAnalyzer）只给数据、排名或"对错判定"，不解释战术意图，也没有问答能力。

本产品做一个网页工具：玩家上传 log，AI 生成复盘报告（可对比顶尖玩家），并支持针对该场 log 的自然语言问答。核心差异化 = **战术意图理解**（例：5 分 36 秒无爆发时喝爆发药，是为了对齐 5 分钟后 BOSS 易伤阶段的 CD——识别为正确决策并解释，而非判为失误）。

**第一版聚焦**：大秘境（Mythic+）单人复盘；中文界面与报告；国服/全球服玩家均可使用。

## 术语约定（大白话）

| 术语 | 含义 |
| --- | --- |
| log | 游戏自动生成的战斗记录，记录每个人每一秒做了什么 |
| WCL / Warcraft Logs | 全球最大的魔兽战斗日志平台，玩家把 log 传上去后得到一个网页链接 |
| 原生 log 文件 | 玩家在游戏里输入 /combatlog 后，游戏生成的 WoWCombatLog.txt 文件 |
| 复盘 | 打完一局后回头分析哪里打得好、哪里可以更好 |
| 对比链接 | 顶尖玩家在 WCL 上那一局 log 的链接，作为"好学生样板" |
| 易伤阶段 | BOSS 在某段时间受到伤害大幅提高的阶段 |
| 爆发 | 玩家短时间大幅提升输出的技能组合 |

## 目标用户

想进步的中高端大秘境玩家：已会打本、能读懂基础数据，但卡分数/层数，需要"下一步练什么、为什么"的指导。首发服务中文用户。

## 功能需求

### FR-1 通过 WCL 链接上传 log（优先路径）
- 描述：用户在首页粘贴 Warcraft Logs 报告链接，系统校验并获取该场大秘境战斗数据。支持全球服（warcraftlogs.com）与国服（cn.warcraftlogs.com）链接。
- 验收标准：
  - Given 一个有效的大秘境 WCL 链接 When 用户提交 Then 系统进入解析流程，并展示该场战斗的副本名、层数、角色与专精信息供确认
  - Given 一个无效链接 / 团本链接 / 非 WCL 链接 When 用户提交 Then 系统用中文明确提示"链接无效/仅支持大秘境/不是 WCL 链接"，并说明可以上传文件代替
  - Given WCL 数据获取失败（网络或平台故障）When 用户提交 Then 系统提示"获取失败，请稍后重试或上传日志文件"，不得卡死或白屏

### FR-2 通过原生文件上传 log（备用路径）
- 描述：用户选择 WoWCombatLog.txt（游戏 /combatlog 生成），**在浏览器本地解析**（Web Worker 分块读取，原始文件不上传服务器，只上传解析后的结构化数据——隐私更好、速度更快、无 200MB 上传压力），解析出其中的大秘境战斗，列出战斗列表供选择。
- 验收标准：
  - Given 标准格式战斗日志文件（≤ 200MB）When 用户选择文件 Then 浏览器本地完成解析，得到大秘境战斗列表（副本、层数、时间、职业专精、成功/失败），供用户选择；期间原始文件不上传服务器
  - Given 非战斗日志格式的文件（如普通文本、图片改名）When 用户选择文件 Then 系统明确提示"这不是有效的战斗日志文件"
  - Given 文件中只有团本记录、没有大秘境记录 When 解析完成 Then 系统提示"未找到大秘境战斗，第一版暂不支持团本分析"

### FR-3 选择战斗与对比对象
- 描述：用户从解析结果中选择要复盘的那一场；可选粘贴一个顶尖玩家的 log 链接作为对比对象（不粘贴也可以复盘）。
- 验收标准：
  - Given 战斗列表已展示 When 用户选择一场并点击"开始复盘" Then 系统进入复盘生成流程
  - Given 用户粘贴了对比链接 When 生成报告 Then 报告包含"与顶尖玩家对比"章节；未粘贴则不显示该章节，其余章节不受影响
  - Given 对比链接无效或非大秘境 When 用户提交 Then 明确报错，且不阻塞不粘贴对比的复盘流程

### FR-4 AI 复盘报告
- 描述：系统对选定战斗生成结构化复盘报告，固定章节如下（按顺序）。**AI 的输入必须是经过 FR-10 预处理后的结构化精简数据，禁止直喂原始 log。**
  1. 总体概览：本场关键指标小结（输出、生存、打断、死亡等）
  2. 关键时机分析：爆发、减伤、打断、移动等时机的表现
  3. 与顶尖玩家对比（仅当提供对比链接时）：双方关键差异点
  4. 可改进点清单：每条 = 现象 → 时间戳/技能证据 → 建议动作
  5. 战术意图识别：哪些"看起来异常"的操作其实是正确决策，解释原因（见 FR-5）
  6. 下一步练习建议：1–3 条可执行的具体练习
- 验收标准：
  - Given 战斗已选定并完成解析 When 用户点击"生成复盘" Then 报告在 120 秒内展示（超时给出"请稍后重试"，不得无限等待）
  - Then 每条"可改进点"必须包含时间戳或技能名证据，不得只写笼统结论（如"打断不够"必须写"在 12:34 漏断 XX 技能"）
  - Then 报告为中文，技能名/专精名/副本名保留游戏内原名（如"暗影烈焰药水"不译成自定义叫法）
  - Then 报告结构为清晰的章节与条目列表，可直接阅读；整体阅读时长 3–8 分钟

### FR-5 战术意图理解（产品命根子）
- 描述：AI 在分析时对每个"可疑操作"必须先做意图判断：检查该操作是否存在战术合理性（对齐易伤/CD 规划/留资源/路线安排/**职业打法技巧**等，其中"职业打法技巧"类领域知识由 **FR-11 社区知识库**提供），再给出**三档结论之一**：① "有意图的正确决策"（列入第 5 章并解释）；② "真实失误"（列入第 4 章可改进点）；③ **"疑似高阶技巧"**——知识库解释不了、但证据链完整（或对比顶尖玩家存在同类操作）的操作，**不武断判失误**，输出"疑似技巧 + 证据 + 推断理由"，并沉淀为候选知识条目待人工验证（见 FR-11）。设计动机（用户要求）：攻略作者可能有意/无意省略细节（如主播把关键细节留给付费粉丝），模型不能盲信知识库，要尝试从 log 参透未公开的手法（例：BOSS 转阶段位移后有落地伤害，顶尖玩家提前控制宝宝就位——宝宝高额被动减伤，落地后第一时间输出）。
- 验收标准：
  - Given 样例"5 分 36 秒无爆发时喝爆发药，目的对齐 5 分钟后易伤阶段"的 log When 生成报告 Then 该操作被归入"战术意图识别"章节并解释原因，而不是出现在"可改进点"中
  - Given 验收样例集（≥ 10 个"看似失误实为正确决策"的案例，覆盖爆发药时机、留爆发、提前减伤、故意不断控等）When 批量生成报告 Then 意图识别正确率 ≥ 80%（案例集与技术设计阶段共同制定，QA 阶段执行）
  - Given 真实失误（如爆发期间长时间空转）When 生成报告 Then 被列入"可改进点"，不得误判为意图操作
  - Given 知识库无法解释但证据完整的异常操作（如转阶段前宠物提前就位规避落地伤害）When 生成报告 Then 该操作被标记为"疑似高阶技巧"并给出证据与推断，而不是列入"可改进点"（不得武断判失误）
  - Given 发现"疑似高阶技巧" When 生成报告 Then 同步沉淀为候选知识条目（origin=inferred、status=candidate），**不注入其他用户的正式分析**

### FR-6 对话问答
- 描述：报告页提供提问框。用户可针对本场 log 提问，AI 结合该场 log 上下文回答，支持追问。回答中凡引用 log 证据必须带时间戳/技能；无法从 log 判断的内容需说明"这是通用建议，不是基于本场数据"。
- 验收标准：
  - Given 报告已生成 When 用户提问"我这波爆发为什么打低了" Then 回答引用本场具体时间戳/技能证据，而非空泛话术
  - Given 用户连续追问（同一话题）When 提问 Then AI 能结合上文回答；单场对话限 10 轮，超出提示"本轮对话已结束，可重新开始"
  - Given 用户提问代练、账号交易等违规内容 When 提问 Then 礼貌拒绝并说明产品定位是"自己进步"
  - Given 用户提问与本场无关的笼统问题（如"我想上 3000 分"）When 提问 Then 回答基于本场数据给出有限建议，并提示"跨场综合分析将在后续版本提供"
  - 性能：单个回答 30 秒内返回，超时提示重试

### FR-7 账号与登录
- 描述：邮箱注册 + 验证码登录（无需设置密码）。登录后可保存历史、使用每日免费额度。
- 验收标准：
  - Given 新用户输入有效邮箱 When 请求验证码 Then 邮件发出，验证码 10 分钟内有效、可重发
  - Given 验证码正确 When 登录 Then 进入产品；验证码错误 5 次锁定该邮箱 10 分钟
  - Given 未登录用户 When 尝试生成复盘 Then 引导注册/登录后再继续
  - 免费额度：每个账号每天（自然日，按用户所在时区）可生成 3 次复盘；额度用尽时提示"今日次数已用完，明天再来；深度复盘即将上线"，第一版不提供付费扣款

### FR-8 历史记录
- 描述：用户可查看自己的历史复盘列表（副本、层数、时间、结果），重新打开报告与问答；可删除记录。
- 验收标准：
  - Given 用户已有复盘 When 打开"我的复盘" Then 按时间倒序展示全部历史，点开可查看报告原文与问答记录
  - Given 用户删除一条记录 When 确认删除 Then 该记录及关联问答从账户移除，他人分享链接同时失效
  - 安全：用户 A 的任何页面/接口均不可访问用户 B 的数据（接口层校验）

### FR-9 一键分享
- 描述：报告页可生成公开分享链接，他人免登录可查看报告（不含账号信息）；用户可随时关闭分享。
- 验收标准：
  - Given 报告已生成 When 用户点击"分享" Then 生成唯一链接，未登录者打开可查看报告全文与问答记录（只读）
  - Given 分享已开启 When 用户点击"关闭分享" Then 原链接立即失效
  - 隐私：分享页不展示注册邮箱、历史列表等账户信息

### FR-10 log 预处理与降噪（数据质量硬性要求，用户特别强调）
- 描述：无论通过链接还是文件获取的 log，**交给 AI 之前必须先做预处理**（类似 Warcraft Logs 的解析过程）：解析原始战斗日志，剔除与复盘无关的噪声数据（环境伤害、无关单位、重复/冗余事件等），按时间线提取并组织关键事件（技能施放、爆发/CD 使用、打断、死亡、移动、增益/减益、BOSS 易伤阶段等），形成**结构化精简数据**后再交给 AI。目的：① 防止噪声干扰 AI 判断；② 控制 AI 的 token 成本。
- 验收标准：
  - Given 一个混有大量无关事件的原始 log When 完成预处理 Then 交给 AI 的结构化数据量满足 **token 预算：≤ 50K token（约 15 万字符）**，且数据量相对原始文件缩减 ≥ 90%（token 预算为主指标，缩减率为辅助参考；统计口径见 TECH-DESIGN.md）
  - Given 预处理后的数据 When 生成复盘报告 Then 报告中的"可改进点"与"意图识别"只引用真实关键事件，不得引用噪声事件
  - Given 预处理 When 生成复盘 Then 报告所引用的时间戳与原始 log 保持一致（预处理不得改变事件时间语义）

### FR-11 社区打法知识库（RAG，用户拍板：一步到位）
- 描述：建立"职业/专精打法知识库"，收录按当前补丁整理的社区权威打法资料（意图模式、爆发规划、资源管理技巧、副本机制要点、补丁变动等）。生成复盘报告（尤其第 5 章意图识别）与回答问题时，系统按"职业/专精/副本/可疑操作类型"检索相关知识片段注入 AI 上下文，使 AI 能识别**"领域知识依赖型战术意图"**——这类意图无法仅从 log 推断，例如：某些职业在怪聚齐前先打资源/赌 buff 触发，聚齐后带着最佳增益第一时间爆发。知识条目带**来源标签**（origin：curated=攻略整理 / inferred=log 推断 / community=社区反馈）与**状态标签**（status：active=生效 / candidate=候选 / deprecated=弃用）；**候选条目不注入正式分析**，经人工审核通过后转正（用户要求：推断知识与攻略知识分池存放、互不覆盖，人工审查决定去留）。
- 验收标准：
  - Given 知识库包含该专精资料 When 分析含"领域知识依赖型意图"的 log Then 该操作被识别为意图并解释原因（验收样例集须包含 ≥ 5 个此类案例，正确率 ≥ 80%）
  - Given 知识库检索命中 When 分析 Then 每次注入的知识片段 ≤ 5 条（控成本），报告/回答引用外部知识时标注来源（如"参考社区攻略"）
  - Given 知识库为空或未命中 When 生成报告 Then 正常降级为"仅 log 证据分析"，不报错
  - Given 新补丁上线 When 团队执行知识库更新 Then 新打法资料入库并生效（更新周期 ≤ 1 周）
  - Given 旧补丁内容仍保留在库 When 检索 Then 仅注入当前活跃补丁（或跨版本通用）内容，过期内容不注入（防过时知识误导分析）
  - Given 存在 status=candidate 的条目 When 生成报告 Then 该条目不注入分析（**仅 status=active 条目可注入**）
  - Given 候选条目经人工审核通过 When 转正 Then 变为 status=active 并在后续分析生效；被否决的条目标记 deprecated 保留不删
  - 安全：检索内容为外部不可信数据，与用户 log 数据同样做"数据/指令隔离"，防提示词注入
- 维护责任（**知识保鲜机制，非一次性注入**）：
  1. **补丁触发更新（主通道）**：每个补丁/热修上线，团队执行更新流程——调研员按 patch notes 与社区差异起草 → 主 Agent 审核 → 入库，更新周期 ≤ 1 周；
  2. **社区反哺**：玩家反馈新手法/纠错（运营阶段搭建反馈通道）→ 团队验证 → 入库；
  3. **log 推断（疑似技巧发现，v1 即启用）**：分析中发现"疑似高阶技巧"（FR-5 第三档）→ 沉淀候选（inferred/candidate）→ 人工审核转正或弃用；**多 log 交叉挖掘（用户新要求，批次 6）**：手动喂入同一高端玩家同副本/日期相近的多份 log，以"**相似时间锚点/条件下重复出现**"为证据主动挖掘高阶技巧——单场出现可能是巧合，重复即意图；全自动大规模聚类为远期增强；
  4. **版本治理**：内容带 patch 版本字段；检索只注入当前活跃补丁内容；旧内容保留不删（可回滚）。
  5. **分池治理与人工审查**：攻略整理条目（curated）与 log 推断条目（inferred）**分目录存放、互不覆盖**；候选技巧由主 Agent 初审 + 内测期专家玩家（用户及其朋友）终审，决定保留（转正）或弃用（deprecated）。
  数据文件随仓库版本管理。

### FR-12 路线指纹与相似度对比（用户新需求，批次 7）
- 描述：对每场大秘境 log 生成"**路线指纹**"：从原始 log 事件流**还原战术波**（用怪物进入战斗的毫秒级时间戳推断哪些怪是 chain 接进来的，解决 WCL 波次合并失真——坦克中途交减伤断了 chain，与正常 chain 的战术路线相同，不应因波次边界差异被判为不同路线）；每波 = 怪物构成（NPC 标识/类型+数量）+ 相对时间锚点。提供两场 log 的**路线相似度比对**（波序列对齐），输出相似度分数 + 差异清单（多/少哪波、顺序差异、合波方式差异）；并建立**阵容画像与相似度**（按专精的伤害类型/爆发风格/功能性刻画阵容——**职业构成相似即相似，含可替换职业**，如菜刀队中某近战换成同定位另一近战；"法刀/菜刀/混合"粗标签仅作辅助参考，不强制二分）。
- 验收标准：
  - Given 两份"战术上同路线"但 WCL 波次不同的 log（一份中途交减伤断了 chain）When 比对 Then 路线相似度 ≥ 判定阈值（判为同路线），不因波次边界差异误判为不同路线
  - Given 阵容相似但个别职业可替换的两份 log（如菜刀队 A 的近战换成同定位另一近战）When 比对 Then 阵容相似度高；法刀大波 vs 菜刀短平快则相似度低（正确识别不匹配）
  - Given 用户上传 log 与多个候选参考 log When 选择对比目标 Then 系统给出"路线相似度 + 阵容相似度"参考排序，供用户挑选（提高分析置信度）
  - Given 挖掘工具（T20）处理多份 log When 分组素材 Then 同路线 log（哪怕 WCL 波次不同）归入同组一起挖掘，不丢数据源
- 实现要点（详见 TECH-DESIGN ADR-003）：chain 归一化与路线指纹**自研**（自解析原始 log）；相似度 = 序列对齐（怪物构成模糊匹配 + 顺序/合波方式容差）；阵容画像 = 自建启发式（专精属性 + 可替换关系）；WCL API 的 dungeonPulls/阵容字段作辅助数据源（字段名开发时核对官方文档）；MDT 规划路线对比（远期可选）用现成 mdt-compression。

### FR-13 自动对比推荐（用户拍板：第一版实现）
- 描述：用户粘贴 WCL 链接并选定战斗/复盘对象后，系统**自动搜索推荐对比目标**——用 WCL 排行榜查询同副本、层数区间（默认 ±1，可配置）、包含所选专精、当前补丁的近期报告，按**"表现优先、相似度其次"**排序推荐：①该专精玩家个人表现（parse 分位/DPS，从高到低，过低者如 parse<80 过滤——防止推荐"被队友带飞"的无效对比）；②路线相似度；③阵容相似度。用户点选推荐项即作为对比目标（保留手动粘贴对比链接的原有路径）。
- 验收标准：
  - Given 用户贴链接并选定复盘对象 When 系统搜索 Then 返回推荐列表，每项含：副本/层数/该专精玩家表现（parse/DPS）/路线相似度/阵容相似度/是否限时
  - Then 排序规则生效：该专精玩家 parse 高的排前，parse 过低者不进列表；parse 相仿时路线相似度高的优先，再次阵容相似度
  - Given 排行榜查询失败/无候选/配额不足 When 搜索 Then 优雅降级为"手动粘贴对比链接"，不阻塞复盘流程
  - Given 用户点选推荐项 When 生成复盘 Then 报告第 3 章对比章节引用该目标
- 配额与缓存：候选 N ≤ 10；zones/NPC 名缓存 24h、结果缓存 1h（按副本+层数+专精）；并行度 ≤ 3；部分候选失败跳过。

## 非功能需求

- 安全：
  - 全程 HTTPS；上传文件做格式与大小校验；数据库防注入；接口做登录鉴权与数据隔离
  - 不收集、不索要游戏账号密码；不实现任何代练/交易功能
  - 验证码有防滥用限流（同一邮箱/IP 频控）
- 隐私：
  - 隐私政策与用户协议页面：说明收集什么（邮箱、上传的 log）、用于什么（生成复盘）、如何删除（FR-8 删除 + 可申请注销账号并清除全部数据）
- 性能：
  - 复盘报告 p95 ≤ 120 秒；问答 p95 ≤ 30 秒；页面首屏 ≤ 3 秒；解析失败/超时必须有可读提示
- 兼容性：
  - 桌面浏览器优先：Chrome/Edge/Safari/Firefox 近两年版本；移动端自适应可用（不做原生 App）
- 合规：
  - 页面显著位置声明"非暴雪官方产品，与暴雪娱乐无关"；不销售游戏内容；提供联系方式
- 可靠性：
  - AI 服务异常时降级提示"服务繁忙，请稍后重试"；用户已上传的 log 不丢失，可稍后继续生成
